# AGENTS.md

Guidance for coding agents working in this repo.

## What this is

A fork of VolGAN (Vuletić & Cont, *Applied Mathematical Finance* 2025; see `README.orig.md`).
It is a conditional GAN that simulates the next day's implied-vol surface and underlying
log-return. Generated surfaces are pushed toward being free of static arbitrage by
smoothness penalties during training, and arbitrage penalties are measured afterwards.
The fork moves the workflow to local CSVs (AAPL prices + Kaggle AAPL option chains),
adds a CLI (`volgan_cli.py`), and adds a toy web demo (`volgan_tvsdne.py`).

## Layout

| Path | Purpose |
|---|---|
| `VolGAN.py` | Core library: grid constants, penalty matrices, BS helpers, data loading (`VolGANData`), `Generator`/`Discriminator`, `GradientMatching`, `TrainLoopNoVal`, `VolGAN()` entry point, `VolGANResults`, `load_results()`, post-hoc reweighting utilities |
| `datacleaning.py` | Upstream kernel smoothing / interpolation (`Smooth` is used by surface generation) |
| `volgan_cli.py` | `--generate-surface`, `--analyze`, `--train`, `--simulate` |
| `volgan_tvsdne.py` | aiohttp demo that renders a random generated surface |
| `volgan_hedging.py` | Paper §5 hedging: surface interpolation + BS pricing (r=0), `Market`, `VolGANScenarios`, `hedge_ratios` (BS delta, delta-vega, VolGAN scenario regression). No yabte dependency. |
| `hedging_backtest.py` | yabte backtest of the hedging methods on rolling one-month straddles (`run_backtest`); one book per method, whose value is the tracking error Z_t. The strategy records vols, BS greeks, hedge ratios and net exposures per rebalance with yabte's `Strategy.record` (`metrics_frame`). Runs on yabte's Python or C++ engine (`--engine`), with identical results |
| `transaction_costs.py` | Bid/ask half-spreads measured from the Kaggle option chains (`data-out/option_half_spreads.csv`, regenerated by running the module), `HalfSpreads`, and `half_spread_column`, the per-row half-spread of a hedging call that yabte charges as a cost (`cost_field`) |
| `notebooks/VolGAN_Hedging.ipynb` | Executed demo of the hedging backtest (uses `run_backtest` from `hedging_backtest.py`). Re-run with `jupyter nbconvert --to notebook --execute --inplace` after changing the model or hedging code. |
| `data-in/` | Price CSV (`date`, `close`) and Kaggle option chains ; see `data-in/README.md`. Not tracked. |
| `data-out/` | Generated surface CSV and trained model pickle `volgan_res.pkl` (both tracked); timestamped pickles and backups are ignored |

## Environment

- Python >= 3.13. `uv sync` installs the locked dependencies into `.venv/`.
- Implied vols are backed out with `pylbr` (pure-Python Let's Be Rational), a git dependency pinned to a commit in `pyproject.toml`. It is imported lazily, so only `--generate-surface` needs it.
- `--device cuda` is the CLI default. Use `--device cpu` where no GPU is usable. Older GPUs need the CUDA 12.6 torch build (see the README).
- **If `AGENTS.local.md` exists, read it.** It holds machine-specific setup (interpreter, GPU, how packages are managed) and overrides this section. It is gitignored.

## Commands

```bash
# Fast smoke test (seconds on GPU, about 1 minute on CPU). Write outputs to a scratch dir, not data-out/.
python -W ignore volgan_cli.py --train --epochs 1 --n-grad 1 --output-path /tmp/x/smoke.pkl
python -W ignore volgan_cli.py --simulate --n-sims 5 --output-path /tmp/x/smoke.pkl --html-path /tmp/x/smoke.html

# Full training (defaults: 10000 epochs, 25 grad-matching epochs). This takes a long time.
python volgan_cli.py --train --seed 0

# Demo server
python volgan_tvsdne.py --port 8080

# Hedging backtest, net of transaction costs (needs the `hedging` extra, yabte >= 0.5.2: uv sync --extra hedging). About 10 s.
python -W ignore hedging_backtest.py --model data-out/volgan_res.pkl --device cpu
```

There is no test suite. Use the smoke test above to check changes.

## Invariants: don't break these

- **Grid**: `LK=10` moneyness points in `M_GRID` (0.6–1.4, K/S) × `LT=8` maturities in `TAU_DAYS`. These are defined once in `VolGAN.py`; import them rather than redefining.
- **Flattening is time-major**: `vec[t_idx * LK + k_idx]` (`entangle_kt` / `detangle_kt`). The smoothness matrices in `GradientMatching`/`TrainLoopNoVal` and the reshape in `simulate` rely on this.
- **Condition vector** (length 3 + 80): `[ann. log-ret t-1, ann. log-ret t-2, 21d realised vol t-1, log IV surface t-1]`. Code slices `condition[:, 3:]` to get the previous surface.
- **Generator output** (length 1 + 80): `[ann. log-ret t, log-IV increment t]`. Surface = `exp(out[:, 1:] + condition[:, 3:])`.
- **Price/surface alignment** is an inner join on date in `VolGANData`. The previous close comes from the full price history, so do not go back to positional trimming.
- **Pickles**: always load with `VolGAN.load_results(path, map_location=...)`, never with `pickle.load`, because saved tensors may be on CUDA. Any new `VolGANResults` field must have a default so older pickles still load. Use attribute access, not 15-way tuple unpacking.

## Reproducibility (the repo is public)

- `pyproject.toml` must stay hardware-neutral: no GPU-specific torch index. GPU notes belong in the README.
- Commit `uv.lock`. After changing dependencies, run `uv lock` and keep torch at the version actually tested (`uv lock --upgrade-package torch==<ver>`).
- No absolute local paths or machine-specific settings in tracked files. Put them in `AGENTS.local.md`.
- Use `--seed` for runs whose results are reported.

## Conventions

- Black formatting. Keep the upstream function names (`DataPreprocesssing` etc.) unless doing a deliberate rename across all callers.
- Keep changes to the upstream math (penalties, `GradientMatching`, training loop) minimal and explain them. The paper is the reference.
- Don't commit data files or large pickles beyond the tracked `data-out/` ones.

## Known issues / backlog

- Model-changing fixes applied together (Nov 2026; models trained before them are in `data-out/seeds/v1/`):
  - `GradientMatching` now calibrates the smoothness weights on log-implied vol, as `TrainLoopNoVal` and the paper (eqs. 11–13) use. Upstream used implied vol there.
  - Realised vol in `DataPreprocesssing` uses the 21 returns up to t-1 (paper eq. 8). Upstream ended at t-2.
  - Surfaces were regenerated with kernel variances (h1, h2) = (0.01, 0.02) (the old values were (0.05, 0.1)). See the comment in `generate_surface`.
- `data-out/surfaces_transform_enhanced.csv` (2016–2020) is the training file. `data-out/surfaces_2016_2023.csv` adds the 2021–2023 Kaggle data for out-of-sample hedging (`hedging_backtest.py --surface-path ... --start 2021-01-04`).
- Hedging (`volgan_hedging.py`): `regression_hedge` keeps the intercept A_t of the paper's eq. 27 on purpose. `volgan_atm` falls back to the underlying alone on the day before expiry (the regression is rank deficient then).
- Terminal Z_T is biased negative for every hedge that leaves vega open (2021–2023 mean without costs, 2% re-strike band: bs_delta −49, volgan_delta −55, volgan_atm −30, bs_delta_vega −3; costs add further negative drift). This is the variance risk premium: implied vol exceeded realised, and at r=0 BS theta is proportional to vega, so unhedged vega means unhedged theta. `volgan_atm` leaves part of the vega open, so look at the mean as well as Z std when comparing it with `bs_delta_vega`.
- Vega hedge blow-up (fixed by default): with `hedge_strike="entry"` the hedging call is struck at the entry spot, so near expiry it is often deep ITM or OTM with almost no vega, and `bs_delta_vega` holds up to ~10^8 calls (`volgan_atm` up to ~10^5); with costs that is ruinous. The default `hedge_strike="current"`, `restrike_band=0.02` re-strikes it at the money when spot moves 2% from its strike (`Roll.hedges`), keeping |phi_atm| ≤ ~2 per straddle at about half the cost of daily re-striking (`restrike_band=0`). The 2% band was chosen because it is better for the BS benchmark than 5%. `max_hedge_ratio` is an optional cap (delta-only fallback), off by default.
- Transaction costs (default on in the CLI, `--cost-mult 1`; `run_backtest(..., spreads=HalfSpreads...)` in code) are charged by yabte as the hedge trades, using its per-asset costs: the underlying a fixed BPS `cost`, each hedging call its `HalfSpread` data field (`build_data`, `make_assets`). `book_history` totals are net of costs and its `costs` column is the cumulative amount paid; `book_value`/`tracking_error`/`summarise(..., net=False)` add it back for the frictionless view. This matches the earlier post-hoc charging from the trade log to ~1e-11. Only hedge trades pay. Options held to expiry settle free. Results with costs: VolGAN beats BS on spread out of sample for seeds 1 and 2, not seed 0.
- Surface generation uses Kaggle's `underlying_last` as spot, and it is often wrong. The price CSV could be used instead.
- IV inversion treats spot as the forward (the `r` argument is ignored) and uses calls only. Deep-ITM calls (m=0.6) produce noisy vols, so OTM puts would be better on the low-strike side.
- `noise_dim` is persisted in `VolGANResults`, but `hidden_dim` and the other hyperparameters are not.
- `DataPreprocesssing`: `sigma_liv` / `sigma_liv_inc` use `np.mean` instead of `np.std` (upstream bug; unused while normalisation stays commented out).
- `GradientMatching` and `TrainLoopNoVal` duplicate the smoothness-matrix construction and compute penalties in a per-sample Python loop (slow; could be vectorised).
- Train/test split is 85/15 with no validation set (`true_val`/`condition_val` are `False`).
